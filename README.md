# Pioneers — a Settlers-of-Catan-style strategy game (perchance)

A faithful single-player + multiplayer recreation of the 1999 PC game "Pioneers" (an offshoot of Settlers of Catan). Procedural maps, host-authoritative multiplayer, works on desktop and mobile (iPhone/Android).

## Quick facts
- Solo vs AI and online multiplayer (rooms, 6-char join codes, host-authoritative).
- **17 board presets** (setup "Map" select): standard, golden, shepherd, iron, forest, brick, hexagon, diamond, longship, ring, star, twins, atoll, archipelago, crescent, **usa**, **europe** — plus any custom random map.
- **Expansions** (setup "Expansion" select): None, **Seafarers**, **Cities & Knights**, or **Both**.
- **House rules** (setup): friendly robber, turn timer (off/30/60/120 s), custom discard threshold (7/9/12/never), custom win VP (8/10/12/15/20), and **Undo last build** (on/off, default on).
- **AI settings** (setup): per-AI difficulty (easy/medium/hard) + play style (balanced/builder/trader/warlord/expansionist).
- Screens: Menu → Setup (solo) / Multiplayer (create/join) → Lobby → Game.
- Responsive HUD (tested at 390×844 and 1920×1080): on desktop the board occupies the left with a 280px right panel (players + log); the in-game HUD floats bottom-left over the board as compact chips — resource tray (`#resTray`, 5 `.resChip`), card counts (`#cardCounts`: 🂠 total resource cards + 🃏/📜 dev-card button that opens the dev-cards modal when >0), C&K commodity + barbarian rows, and the action row (`#actions`, icon-only `.actBtn` buttons). On phones the floating HUD and right panel stack statically below the board, the players card hides, and the topbar wraps to a second line so the phase text is never truncated.
- While editing (unsaved preview), the server-plugin runs a single-tab emulator — real cross-tab multiplayer needs the user to click **Save**.

## File layout
- `main.pjs` — only `createServerSocket = {import:server-plugin}`. Perchance config layer.
- `index.html` — all CSS, all screens' HTML, and the authoritative server script (`<script type="text/x-server-plugin">`). The setup screen carries the preset/expansion/house-rule/AI controls.
- `src/rand.js` — seeded PRNG (mulberry32) used for reproducible maps; every map is keyed by a seed string shown in the lobby. Also the audio bridge: `setAudioHook(fn)` registers a callback and `snd(name)` fires it (no-op when unset, so headless benchmarks don't crash) — the engine modules call `snd(...)` on every sound-worthy event and main.js maps those names onto real WebAudio sounds.
- `src/sfx.js` — procedural WebAudio sound effects, zero assets: `createSFX()` returns named one-shots (`click/ui/place/build/city/ship/dice/trade/card/steal/robber/undo/error/knight/improve/progress/notify/turn/attention/victory`) synthesized from oscillators + filtered noise, plus `unlock()` (lazy AudioContext resumed on first pointer/key/touch interaction), `setMuted`/`isMuted` (persisted in `localStorage 'pioneers.sfxMuted'`).
- `src/board.js` — procedural map generation: `tiny`/`standard`/`large`, shapes `classic`/`blob`/`elongated`, plus the 17 named presets (some introduce `sea` hexes for Seafarers). Produces vertices, edges, hexes, ports, bounds, `hexSize` (all in abstract board units; the renderer scales). Seafarers boards get sea hexes, gold hexes, and island grouping (`islandOf` map + `islands`).
- `src/rules.js` — the full Catan engine (pure functions, operates on a serializable `game` object): setup snake order `[0..n-1, n-1..0]` **rotated by a random seed-derived starting player** (so who picks first varies; the setup first-picker also takes the first action turn), dice/production, robber+steal, dev cards (Knight/Year of Plenty/Road Building/Monopoly/Victory Point), ports, bank trade, domestic trade offers (targeted or all, with expiry), longest road, house rules (friendly robber, turn timer, custom discard threshold, custom win VP), **undo** (`undoAllowed` + `undoStack`; `pushUndo` records builds during a player's own action turn and `undoBuild` reverses them with refunds — stack cleared on roll and end-turn so there are no build→roll→undo exploits), Seafarers (ships, pirate, gold production, island bonus VP), and it wires the C&K engine via `setRulesHooks`. Each production roll records `lastGains` (per-hex `{pid, amt, kind}` — kind is `gold`/commodity where relevant) plus a bumping `gainsId` so the UI can animate new card gains and MP clients can replay them. Exports `createGame` (takes top-level `opts.cnk` / `opts.seafarers` booleans, NOT a nested `expansions` object), all `place*`/`build*`/`rollDice`/`endTurn`/`tradeWithBank`/`discard`/`stealFrom`/`yearOfPlenty`/`monopoly`/`buyDevCard`/`playDevCard`/`checkWin` + `valid*` helpers + `getTradeRate`, and re-exports the C&K API.
- `src/cnk.js` — Cities & Knights engine: commodities (paper/coin/cloth), three improvement tracks (politics/science/trade) with level-up → progress cards, knights (build/upgrade/activate; moving the robber on activate; **buildKnight pushes an undo record** so knights can be undone too), progress cards (alchemist/crane/intrigue/monopoly/master, bishop/constitution/merchant, etc.), the barbarian attack cycle (attacks every 3 turns once total improvements ≥ 6; defenders earn commodities + solo defender +1 VP; undefended → weakest city sacked), Defender of Catan (+2 VP, 🛡). Hooks into rules via `setRulesHooks({ produce, checkWin })`. `pickBestNumber` scores only the player's own structures (fixed this session — was counting all players' vertices).
- `src/ai.js` — AI: `aiSetupStep`, `aiChooseAction`/`applyAiMove`, `aiBankTrade`, `aiProposeTrade`, `aiRespondToTrade`, `aiTargets`, `aiHandlePending` (discard/robber/pirate/steal/year/monopoly + all C&K pending: alchemist/crane/intrigue/monopolyC/bishop). Difficulty (easy/medium/hard) controls decision noise; play style (balanced/builder/trader/warlord/expansionist) biases resource need, dev-card buying, pirate placement, and settlement thresholds. When an AI offers a trade that targets a human, main.js pauses the AI's turn for 15 s (banner countdown) before the AI moves on.
- `src/save.js` — `serializeGame(game)` / `deserializeGame(save)`: JSON round-trip of the whole game state, including C&K state (commodities/improvements/knights/progress/defender/barbarian), the gain-animation payload (`lastGains`/`gainsId`), and the undo feature (`undoAllowed`/`undoStack`, plus each log line's `turn` for the turn headers). Used as the MP wire format. No single-player save/load UI yet.
- `src/render.js` — canvas renderer (2D): ocean with animated waves, beveled hexes, number tokens with probability dots, ports (**each port shows its ratio badge — ⚓ "3:1" or resource "2:1" — directly under the port circle**), roads/settlements/cities, **ships, pirate, gold coin** on gold hexes, robber, hover/pending highlights. Exports `fitView`, `boardToScreen`, `screenToBoard`. Canvas is 2D (no preserveDrawingBuffer needed), sized to `#boardWrap`.
- `src/input.js` — pointer-based pan (single finger), pinch zoom + wheel zoom (zoom-at-point), tap-to-place with hit-testing filtered by the current pending action. `setPointerCapture` is wrapped in try/catch.
- `src/ui.js` — HUD: bottom-left chip stack (`#hudLower`) with the resource tray (`#resTray`, 5 `.resChip` in `RESOURCES` order so the gain animation's `tray.children[idx]` lands on the right chip), card counts (`#cardCounts` — 🎴 total resource cards in `#totalCardsNum`, and a 🃏/📜 dev-card button in `#devCards` that becomes clickable and opens the dev-cards modal when the player holds any; `.off` class when empty), the C&K commodity row (`#commodityRow`) and barbarian indicator (`#barbarianRow`, "🪓 Barbarians cur/next + 🛡 defender name"), and the icon-only action row (`#actions`, `.actBtn` buttons: Road/Ship/Settle/City/Trade/Undo always; Buy/Play for base; Improve/Knight/Upgrade/Activate/Progress for C&K). Right side is the 280px `#rightPanel` (players card + log). **Player list rows** are two-line cards: line 1 = dot/name/VP/tags, line 2 = `.plStats` chips showing every player's hand-card count (🎴), dev/progress-card count (🃏/📜), and remaining build pieces (🛤 roads / 🏠 settlements / 🏰 cities / ⛵ ships on Seafarers) with a `.low` red style at 0. Each `.actBtn` build/play button carries a small `×N` count badge (`.cnt` + `.hasCnt`) — remaining pieces on Road/Ship/Settle/City, held cards on the base-game Play button / C&K Progress button; the Ship button only appears in Seafarers games. The `#turnBadge` gains a pulsing `.yourTurn` glow during your action turn. Player list shows 🛡 Defender of Catan tag and defender +2 in displayed VP; **log with "— Turn N —" headers** (`renderLog` groups entries by their stored `turn`; auto-scrolls to newest). **Build guide** (`btnGuide` in the topbar → `showBuildGuide`, a guide-kind modal listing every build's resource costs — Road/Settlement/City/Dev Card with 🧱/🌲/🐑/🌾 chips, Ship on Seafarers, Knight + the three City-Improvement tracks with their commodity costs on C&K — plus a Victory Points table), **trade negotiation UI** (`renderTradeResponses` floats a centered panel above the board listing every open trade with per-player status chips ⏳/✓/✗ — clicking a ✓ chip completes that trade when it's your turn; `renderIncomingTrades` shows \"✓ You accepted — waiting for X\" / \"✗ You declined\" / Accept+Decline buttons; the trade modal's \"Active offers\" section shows per-player status + a \"Trade with X\" button + Withdraw; every build action button's `title` tooltip shows its cost via `COSTS`/`costLabel`). All modals (trade, dev cards, discard, steal, year, monopoly, game over, how-to-play, **improvement, progress, knight, alchemist, crane, intrigue, monopolyC**), the **resource-gain card animation** (`animateGains`: spawns parchment cards at producing hexes, flies them to the player's tray / the recipients' player-list rows, with a turn-badge fallback on narrow layouts where the players card is hidden; JS-driven with rAF + setTimeout fallback), lobby rendering, forced-modal chain handling.
- `src/main.js` — the controller: wires everything, runs the game loop, drives the AI, and is the multiplayer client. Host processes C&K actions (`improvement`, `knight`, `startKnight`, `upgradeKnight`, `activateKnight`, `progress`, `alchemist`, `crane`, `intrigue`, `monopolyC`) and the `undoBuild` action. **Trade negotiation**: offers carry a `responses:{pid:'a'|'d'}` map — `recordTradeResponse` records an accept only if the acceptor has the cards (and frees `tradeWait`/kicks AI once all human targets respond), `doAcceptTrade` records an accept instead of auto-completing, `cancelTrade` withdraws (if you're the offerer) or records a decline (if you're a responder), and the turn player completes a trade by choosing a partner via the `completeTrade {id,pid}` action (the one place an accept is finalized) — the turn taker picks which accepting player to actually trade with. `aiTargets` skips already-responded AIs, `aiTradeStep` records AI accept/decline responses, and `aiCompleteOwnTrades` completes the current AI turn-player's own offer with its first acceptor. Logs trade outcomes: accepts, withdraws (offerer cancels), and declines — both a human declining via `cancelTrade` and an AI declining a targeted offer in `aiTradeStep`. **Sound**: `createSFX()` is instantiated once, wired into the engine via `setAudioHook`, and the trade/error paths call `sfx.trade()/ui()/error()` directly; `sfxCue()` (called from `afterChange`) plays a rising **turn chime** when your action turn starts, a soft **notify** when another player's turn starts, an **attention** beep when a pending action needs you, and the **victory** fanfare when the winner changes; the 🔊 `btnSfx` topbar button toggles mute (persisted) and the page unlocks the AudioContext on first pointer/key interaction. Reads the solo/MP undo toggles into `createGame({undoAllowed})`. Exposes `window.__pioneers` debug handle (`game`, `view`, `overlay`, `mode`, `myPid`, `isHost`, `room`, `doAction`, `performLocal`, `net`, `ui`, `input`, `renderer`, `sfx`).

## Game loop / timing
- The render loop uses `setTimeout(16)` rather than `requestAnimationFrame`. rAF can stop firing in some preview environments (wedged-preview state) and the setTimeout loop is guaranteed to tick, so the game always renders. `performance.now()` is passed as the animation time.
- The board canvas is resized by measuring `#boardWrap` each frame and calling `renderer.resize` when the rounded size changes (a `ResizeObserver` is also attached where available).

## Multiplayer architecture (host-authoritative)
- **Server script** (in `index.html`) keeps durable rooms in `state` bytes starting at offset 16 (magic `PION`, format `FMT=1`). The emulator mirrors `self.state` as a `Uint8Array`; production persists it.
- Rooms: `room:{code}` pubsub topic; codes are 6 chars from `CODE_ALPHABET`. Settings are fixed at creation (size/shape/seed/aiCount/expansion/house rules). MAX_PLAYERS=4, MAX_ROOMS=200, 10-min grace before an empty room is swept.
- **Important**: the server runtime rejects non-string sends — the server always wraps objects via `s2(conn, obj)` / `pub(topic, obj)` (JSON.stringify). Never call `conn.send(obj)`/`pubsub.publish(obj)` with an object.
- Messages: `create_room`, `join_room`, `leave_room`, `start_game`, `state_update` (host pushes `save`), `action` (non-host intent, relayed to host as `relay`), `chat`. Server → client: `welcome` (connId), `you_are_host`, `lobby`, `state`, `relay`, `chat`, `error`.
- Host runs rules + AI and broadcasts `state_update`; non-hosts send intents. The host applies actions from `relay` after `hostCanProcess(pid, action)` (turn/pending/phase validation). The host's own `state` messages are ignored (`isHost && !justPromoted`), except right after promotion.
- **Host promotion**: on host disconnect, `maybePromote` picks the first connected player, sends `you_are_host`, and pushes the current state.
- **Disconnect → AI, rejoin → human**: `leaveCurrentRoom` sets the seat `connId=null, isAI=true`; the host's lobby handler flips the matching game player to AI and `kickAI`→`ensureProgressable` catches a stalled human whose seat is gone. Rejoining with the same name reclaims the seat (the server rejects only names currently held by a connected player); the lobby handler flips the player back to human.
- **Verified (two-socket test in the preview emulator)**: disconnect → server marks seat AI → host logs "X has disconnected — the AI takes over their pieces." and the AI plays the absent human's setup/turns so the game keeps moving; rejoin with the same name → host logs "X has rejoined as a human player.", the rejoiner receives the current save (client `adoptState` resumes it), and the rejoined player's socket actions (setup placement, roll) are processed by the host; the `ensureProgressable` backstop also converts a *stale* human seat to AI when any action fires `afterChange`; a second connection using a currently-connected name is rejected ("That name is already connected."). Caveats: solo mode is local-only with no persistence, so "leave and come back" only exists for rooms (MP or host+AI seats) — and in the unsaved preview the emulator wipes room state on reload, so full-reload rejoin is only testable after Save (production persists rooms).
- **net.js** queues outgoing messages until the socket opens, and re-sends `join_room` on reconnect for players with a room identity. Client guards: lobby/state/chat messages are ignored while `mode === 'menu'`.

## AI
- `src/ai.js` as described above. Host drives AI via `aiStep` (in main.js) on a paced timer to make turns feel like a real game rather than instant: ~800ms before the "X is thinking…" beat, a ~1.1s think pause, then the dice roll, a ~1.4s pause after the roll, and ~800ms between subsequent actions (650ms during setup placement). A `kickAI`/`aiStep` orphan-timer bug that could make steps fire back-to-back was fixed with an `aiBusy` re-entrancy guard. A 4-player full game averages ~180 turns (AI-driven benchmark; ~15-20 min real time). AI games complete reliably (17-config regression + 22-trial benchmark pass with zero errors).
- C&K AI: buys improvements (track chosen by `aiBestTrack` — returns `null` when all tracks are maxed, which the crane handler treats as a no-op rather than crashing), activates/upgrades knights, plays progress cards (alchemist picks the best roll via `pickBestNumber`, crane advances the best non-maxed track, intrigue/monopolyC target the richest opponent, bishop places the robber), and responds to barbarian attacks (defends when total active strength ≥ barbarian strength).

## Known limitations
- Cross-tab/real multiplayer can only be tested after **Save** (the editor preview runs a single-tab server emulator).
- No single-player save/load UI yet — serialization exists (`src/save.js`) and is used as the MP wire format, but there's no button to persist/reload a solo game.
- Longest road is recomputed on every build (fine for ≤4 players).
